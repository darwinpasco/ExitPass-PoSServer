# ExitPass POS Server Digital Sales Invoice Template Contract Implementation Note v1.0

## Purpose

This slice adds a stable JSON template contract to the existing read-only Digital Sales Invoice endpoint so downstream UI, print, and PDF work can consume a predictable structure without changing fiscal document creation, numbering, or idempotency behavior.

## Contract Version

- `templateContractVersion`: `digital-sales-invoice-json-v1`
- `fiscalTemplateFamily`: `PH_DIGITAL_SALES_INVOICE`
- `renderFormat`: `application/json`
- Display responsibility: `structured_fiscal_data_only`

POS Server provides structured fiscal data and contract metadata. UI, print, PDF, and presentation renderers remain responsible for layout. Placeholder text is not final BIR template text.

## Sections Defined

The contract metadata classifies the Digital Sales Invoice response into these sections:

- `header`
- `seller_site_pos_identity`
- `document_identity`
- `fiscal_numbering`
- `parking_payment_references`
- `line_items`
- `discounts`
- `taxes`
- `tenders`
- `totals`
- `audit_hash_status`
- `footer_disclaimers`
- `deferred_placeholders`

## Field Posture

The contract uses explicit field posture values:

- `required`: expected in the JSON contract for normal rendering.
- `optional`: available when the underlying fiscal document read model has the value.
- `placeholder`: present only as safe placeholder metadata or text.
- `deferred`: intentionally not generated by this slice.
- `not_available`: reserved for future contract versions when a field must be declared unavailable.

Required sections include header, seller/site/POS identity, document identity, fiscal numbering state, line items, tenders, totals, and audit/hash/status. Optional sections include parking/payment references, discounts, and taxes. Footer/disclaimer text is marked as placeholder. QR, PDF, HTML, Digital SI URL, and final statutory text are declared as deferred placeholders only.

## Endpoint Response Impact

Endpoint:

- `GET /v1/fiscal-documents/{fiscalDocumentId}/digital-sales-invoice`

Successful responses now include `templateContract` beside the existing `render` payload. The existing render fields remain available for fiscal document identity/status, business day, site POS Server/channel terminal/fiscal identity, fiscal numbering, parking/payment/finality/vendor references, lines, discounts, taxes, tenders, totals, semantic hash/version/status, and assigned/not-assigned numbering state.

Failure responses for missing documents or persistence failures remain fail-closed and do not include a template contract or render payload.

## Intentionally Not Implemented

This slice did not implement PDF generation, HTML rendering, QR code rendering, BIR X/Z reports, Annex E reports, fiscal numbering changes, idempotency changes, fiscal document creation changes, Central PMS changes, payment finality ownership, gate behavior, ExitAuthorization behavior, refund authority, or reversal authority.
