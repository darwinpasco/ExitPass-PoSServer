# ExitPass POS Server BIR Annex E Field Dictionary v1.0

## 1. Scope

This dictionary covers the 10 E-1 header facts and all 32 physical E-1 detail columns in AE-SRC-001 worksheet `E-1`. The workbook displays 29 official field numbers across those 32 detail columns. This dictionary preserves physical columns rather than collapsing NAAC or Solo Parent into another field.

The source does not prescribe maximum character lengths, numeric scale, nullability, or electronic serialization. Workbook column widths are recorded as layout evidence only. Internal runtime types and validation approved by `Z-009B-USER-APPROVAL-001` remain ExitPass decisions pending applicable external acceptance.

All samples are synthetic. Amount samples use PHP major-unit display with two decimals; authoritative POS values remain integer minor units.

## 4. Common validation posture

- All monetary authoritative inputs are integer minor units. Decimal formatting is an output projection only.
- Currency partition is inherited from the governing Z. E-1 has no physical currency column, so only one approved currency may appear in one profile instance.
- A missing mandatory authoritative source fails closed. An unresolved field is not emitted as guessed zero.
- Historical header values must be snapshotted or bound to an immutable approved profile. Regeneration must not read mutable current configuration.
- Customer identities, beneficiary identities, raw statutory IDs, evidence, ticket numbers, plate numbers, and payment credentials are prohibited from E-1.
- Official field numbers and physical columns remain separately recorded until AE-DR-006 resolves the workbook numbering ambiguity.
- Internal PHP formatting, date, filename, and blank/zero recommendations are not regulatory approvals; AE-DR-019A and AE-DR-011A keep those layers separate.
- Unknown mandatory values always block generation. Zero is permitted only when an authoritative source records zero under the approved AE-DR-011/021 posture.
